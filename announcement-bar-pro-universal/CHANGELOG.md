# Changelog (universal package)

## 2.3.0 "Pro Max" — 2026-11-07
- Author is now **3DP SIA**; the extension link opens the support e-mail extension@3dp.lv (`install.xml`, `install.json`).
- **Free-shipping progress** (new message type): amount in the store's default currency, a per-language text with `{remaining}` and a per-language text for when the amount is reached (required where the text is set), optional thin progress bar. The remaining amount is computed on the server from the cart subtotal (without tax) and formatted in the visitor's currency. After OpenCart's own AJAX cart requests (`checkout/cart` and `common/cart` routes, OpenCart 3 and 4, via jQuery `ajaxComplete`) the bar asks a small read-only endpoint (`…/cart`, GET `ids`, same-origin only, JSON, no session changes beyond what OpenCart does on any page view, never outputs errors) and updates text and bar in place.
- **Coupon code with Copy:** optional per message (A–Z, 0–9, `-`, `_`, max. 32, stored uppercase). Dashed code chip + Copy button (Clipboard API with `execCommand` fallback), visible "Copied!" feedback announced through `aria-live`, new **copies** counter.
- **A/B test:** optional variant B per message (text, phone text, button text) behind a checkbox. Every browser gets a stable random variant (`localStorage` `abp_ab`, without storage: A). Views, clicks and copies are counted per variant; the admin list shows both CTRs and stars the better one once each variant has at least 100 views. **Use B as the main text** (POST, *modify*, `user_token`, double-click safe) copies B into A in every language that has a B text, switches the test off and keeps B's counters as the main counters.
- **Weekly schedule:** weekdays (any subset) and an optional daily window HH:MM–HH:MM that may cross midnight (it belongs to the day it starts on), in the store's time zone, together with the start / end dates. Checked on the server at render; messages outside their window are rendered hidden and the script switches them on and off while the page stays open (server clock + store time-zone offset, so a wrong visitor clock does not matter). Server and script share the same rules (unit-tested in PHP).
- **Category / product targeting:** optional lists (max. 200 each) chosen with autocomplete chips that use each OpenCart version's own catalog autocomplete route (`catalog/category/autocomplete` / `catalog/category.autocomplete`, `|` before 4.0.2.0). With lists set, a message shows only on those category pages, on product pages of those products and on product pages of products in a chosen category; works together with pages, stores, customer groups and devices. Unknown IDs are rejected.
- **Export / import (JSON):** Export downloads every message (texts keyed by language code, statistics left out). Import accepts our export format up to 1 MB, maps language codes to this shop's languages (unknown ones are skipped and listed), runs every message through the same normalisation, validation and sanitizing as the form and creates it switched off; the result reports created / skipped. *modify* + `user_token`; the file content is never trusted.
- **Design — storefront:** module-wide **Style** setting with a per-message override: Solid, Gradient (derived from the bar colour), Soft (light tint, dark text), Minimal (near-white with a thin top accent line) and Glass (translucent with backdrop blur, solid where the browser cannot blur). Every style keeps the automatic-colour logic and a contrast of at least 4.5:1 (Glass is checked against both a white and a black page behind it; custom colours below 4.5:1 are corrected in the derived styles, Solid custom colours are still not changed). Pill buttons (filled / outline / link per message), SVG close icon, refined typography (font inherited from the theme), smooth progress bar, rotation effect **fade | slide**, optional **prev / next arrows** (buttons with labels, keyboard accessible), `prefers-reduced-motion` respected, no horizontal scroll from 320 to 1920 px. The phone / desktop rules of 2.2.0 are unchanged.
- **Design — admin:** each version's own Bootstrap (3 / 5). The message form is grouped into cards (Content, Button & coupon, Free shipping, A/B test, Schedule, Targeting, Appearance) with one language switcher for all per-language fields and a sticky **live preview** that loads the shop's real storefront CSS / JS from the catalog URL into a sandboxed frame (computer / phone width, version A / B, cart below / above the amount) and updates while typing. The list has a colour swatch, status badges, badges for free shipping, coupon, A/B, schedule, targeting, device and missing languages, views / clicks / copies and CTR (per variant for A/B). Settings are grouped with help texts and a visual style picker. The admin script and styles are shared byte-identical by both kits (`build.sh` checks them too).
- **DB schema 7:** `abp_message` gets `type`, `threshold`, `progress_bar`, `coupon`, `copies`, `ab_test`, `views_b`, `clicks_b`, `copies_b`, `weekdays`, `time_start`, `time_end`, `categories`, `products`, `style`, `button_style`; `abp_message_description` gets `success_text`, `text_b`, `mobile_text_b`, `link_text_b`. Same idempotent migration as 2.2.0 (`SHOW COLUMNS` before each `ALTER TABLE … ADD COLUMN`), only for users with *modify* permission; upgrades from 2.1.x get the 2.2.0 columns in the same run. TEXT columns have no `DEFAULT` (MySQL refuses it). Existing messages keep the 2.2.0 outline button (`button_style` default `outline`; new messages start with `filled`). Until the admin page is opened the storefront keeps working on the old schema (neutral values for the new columns, no cart endpoint).
- **Upgrade safety:** messages, settings and the per-message dismiss keys are kept — a message that uses none of the 2.3.0 features has exactly the same key as in 2.1.x / 2.2.0, so closed messages stay closed.
- New strings in English, Latvian and Russian (admin), Copy / Copied / previous / next in the storefront.
- Fix found by the real-shop test: admin links printed with `|e` were escaped twice (`&amp;amp;`), which lost `user_token`; links already HTML-encoded by OpenCart are printed as they are. Fix: the admin stylesheet link must not sit between `column_left` and `#content` (OpenCart 3 positions `#content` with a sibling selector). OpenCart 4 admin model: no notice when a message without `device` is saved.
- Tested on real OpenCart (MariaDB 11.4, Chromium): 3.0.5.1 upgrade 2.2.0 → 2.3.0 with 2 messages + every feature through the admin UI and storefront (1366 / 390 px) 72/72; 4.1.0.4 fresh install 63/63; schema unit test 95/95; demo test 50/50.

## 2.2.0 — 2026-11-07
- **Phone text (optional, per language):** a short text that replaces the normal text on screens narrower than 768 px. Both texts are rendered and a CSS media query switches them. Same sanitizing and HTML-mode rules as the text, `{countdown}` works in it, and it is part of the per-message dismiss key (messages without a phone text keep their 2.1.x key, so closed messages stay closed after the upgrade).
- **Device targeting per message:** all devices / computers only (768 px and wider) / phones only. Messages for the other screen size are hidden by CSS and left out of rotation, marquee and stack; the script rebuilds the bar when the viewport crosses 768 px (rotation, resize). With nothing left, the bar hides and header offsets are restored exactly as when it is closed.
- **Statistics (counters only):** views and clicks per message, CTR in the admin list, "Reset statistics" per message. The storefront sends one view per message per browser session when the message is really shown, and one click when its button or a link in it is used (`navigator.sendBeacon`, fallback `fetch` keepalive). Nothing is sent when the visitor has Do Not Track or Global Privacy Control on. The endpoint (`…/track`) accepts only POST `id` + `type` (view/click), counts only enabled messages, at most one view and one click per message and 100 events per OpenCart session, always answers with an empty 204 and never outputs errors. No personal data is stored and the module sets no cookies of its own.
- **Duplicate** a message from the list: all languages and settings are copied, the copy is switched off and starts with zero statistics.
- DB schema 6: new columns `abp_message.device`, `views`, `clicks` and `abp_message_description.mobile_text`. Upgraded shops get them through an idempotent migration (`SHOW COLUMNS` check before each `ALTER TABLE … ADD COLUMN`), run when a user with *modify* permission opens the module page. Until then the storefront keeps working with the 2.1 columns.
- `mobile_text` is `TEXT NOT NULL` without a `DEFAULT`: MySQL refuses a literal default on `TEXT` columns. Existing rows get `''` when the column is added and every insert sets the value.
- New admin strings in English, Latvian and Russian.
- Hardening after review and real-shop tests: the statistics endpoint never touches the visitor's session (no race with cart or login), counts only same-origin requests and messages inside their date window; older browsers' Do-Not-Track values are honoured; no width gap between the phone and computer rules; a double click on Duplicate creates one copy (both versions). OpenCart 3: Duplicate and Reset are plain buttons that post their own form (the admin's "submit every form" helper for IE submitted the settings form instead).
- Tested on real OpenCart: 3.0.5.1 upgrade 2.1.2 → 2.2.0 with 2 existing messages (migration, idempotency, phone text, device, statistics, duplicate, reset, error log) 22/22; 4.1.0.4 fresh install 15/15.

## 2.1.2 — 2026-11-06
- **Readable automatic colours:** the text colour is now the one with the higher WCAG contrast (white or near-black), not a fixed brightness threshold. On the OpenCart 4 default blue this changes white text (3.2:1) to dark text (5.9:1).
- When neither text colour reaches 4.5:1 (mid-tone theme colours), the bar background is darkened or lightened just enough to reach it. Checked over 4,913 colours: lowest contrast 4.50:1.
- Custom colours are not changed.
- README: correct upgrade steps for OpenCart 4 (its installer refuses a package that is still installed; checked on 4.1.0.4).

## 2.1.0 — 2026-11-06
Supersedes all earlier packages (2.0.x for OpenCart 3 and for OpenCart 4).

- **One package for every version:** the same `announcement_bar_pro.ocmod.zip` installs on OpenCart 3.0.x and 4.0.x/4.1.x. Each installer picks its own files.
- **Automatic theme adaptation**, with no settings needed:
  - Fixed or sticky headers move below the bar while it is visible.
  - Bottom fixed elements (cookie banners, mobile tab bars) lift a bottom bar.
  - The bar's z-index goes above the theme's fixed bars.
  - Sticky top and the bottom bar work with absolutely positioned page wrappers.
  - Missing Font Awesome drops the icons.
  - RTL languages are mirrored.
- **Footer fallback:** themes whose header template has no `<body>` still get the bar. A second event is registered automatically, also on upgrade.
- **Automatic colours** (new "Colours" setting, default for new installs): the theme's main colour with readable text. Upgraded shops keep their custom colours.
- **Works out of the box:** a fresh install with no messages is switched on.
- A theme that renders the header twice shows only one bar.
- The OpenCart 3 files cannot be called directly when they sit unused inside an OpenCart 4 shop.
